Why Terminal Talk

There are voice tools for coding. This is the one for parallel agent sessions.

Most voice-AI tools in this space solve dictation or wrap a single chat in a microphone. Terminal Talk does something narrower: it gives every parallel Claude Code or Codex session its own voice, colour, and queue position so you can run four agents at once and follow them by ear.

vs

Aider voice

Aider speaks code at you while you dictate code back. Voice-to-code, single agent. Terminal Talk doesn't replace Aider's voice mode — they live at different layers. Use Aider's voice for dictation; use Terminal Talk to listen to all your other agents.

vs

Voice Mode

Voice Mode is a voice wrapper around a single Claude or Cursor session. Single-agent conversation. Terminal Talk is multi-agent monitoring — colour-coded narration of every Claude Code, Codex CLI, and Desktop session running side by side, plus per-session focus and mute.

vs

ElevenLabs MCP

ElevenLabs MCP routes premium TTS into Claude Code. Voice quality plus an MCP plug-in. Terminal Talk includes an MCP server too, but adds session identity, colour, focus/mute, transcripts, hooks, and free Edge voices by default — ElevenLabs is the voice; Terminal Talk is the orchestration around it.

vs

Cursor dictation

Cursor dictation is voice input into Cursor. Useful, but it's input, not output, and only inside Cursor. Terminal Talk is output across Claude Code, Codex CLI, Claude Desktop Code, and Codex Desktop — and it works with Cursor's plain-text terminals too if you run Claude/Codex CLI inside them.

If you only ever run one assistant in one window, the voice tools above probably suit you. If you have four terminals open and want each to sound different, Terminal Talk is the one tool in this list that's actually built for that.

Install

Three commands, under two minutes

  1. Install Python 3.10+ and Node.js 18+ if you don't already have them.
  2. Clone the repo and run install.ps1 — installs deps, pre-downloads the wake-word model, adds Desktop/Start Menu shortcuts, and asks which hooks you want registered.
  3. Open Claude Code, Codex CLI, Claude Desktop Code, or Codex Desktop. Assistant replies feed the same Terminal Talk queue where supported. Say "hey jarvis" over highlighted text to read it from any app.
PS> git clone https://github.com/benfrancisburns-creator/terminal-talk
PS> cd terminal-talk
PS> .\install.ps1
Windows 10/11 · Python 3.10+ · Node 18+ · Microphone
macOS works the same way via install.sh (Homebrew + brew install node python@3.12 portaudio first). Linux port still in progress; the Windows-only mic-watcher (auto-pause when another app dictates) no-ops on macOS today. Uninstall on Windows with .\uninstall.ps1.
Privacy

What leaves your machine

One outbound call at runtime, only when you trigger it. No telemetry, no analytics, no background traffic.

What goes out — only when you ask

  • TTS text → Microsoft, to Edge's neural voice endpoint — the same one Edge browser's "Read Aloud" uses. Sent on every reply you hear and every "hey jarvis" highlight. Free, no API key, governed by Microsoft's consumer service terms.

What never happens

  • No audio is uploaded; wake-word runs offline on your CPU
  • No usage telemetry or analytics of any kind
  • No background network calls when idle
  • No account, no sign-up, no email required

One-off on install: install.ps1 downloads the ~30 MB wake-word model from HuggingFace, then runs offline forever after. Optional paid swap: configure the OpenAI TTS fallback if you want API terms with no-training guarantees instead of Microsoft's consumer ones.

FAQ

Likely questions

Is it really free, with no sign-up?

Yes. It uses Microsoft Edge's built-in neural voice endpoint (the same one Edge browser uses for "Read Aloud" — no API key required) and openWakeWord for offline wake-word detection. An OpenAI TTS fallback is optional if you'd rather pay for premium voices.

What about macOS and Linux?

macOS is supported. The synthetic-keystroke helper uses Quartz CGEventCreateKeyboardEvent, the foreground PID comes from NSWorkspace.frontmostApplication, and the process tree is walked with psutil. First launch prompts for Accessibility (synthetic Cmd+C) and Microphone (wake-word listener); both grants are one-time. The Windows-specific WMI mic-watcher (auto-pause when another app dictates) cleanly no-ops on macOS — that feature is the only one still Windows-only. Linux is next; POSIX install scaffolding and shared Python hooks (install.sh, app/posix_hooks.py) are already in the repo. PRs welcome.

Can I change the wake word from "hey jarvis"?

Yes — the wake model is a drop-in swap from the openWakeWord project. Documented in the README. You can also disable the wake word entirely and just use Ctrl+Shift+S.

Which coding agents does it support?

Claude Code and OpenAI Codex CLI are built in. Claude uses hooks for streaming, smart tool-call narration and permission alerts. Codex uses native hooks plus local ~/.codex/sessions rollout logs for commentary/final messages, shell and patch progress clips, and heartbeat working-state detection. Claude Desktop Code and Codex Desktop can also be matched into the same Terminal Talk registry where their local session metadata is exposed. The "hey jarvis / highlight and speak" path works with any app.

How do I uninstall?

Run .\uninstall.ps1. It reverses every change, restores your Claude Code settings from the backup created at install time, and removes Startup, Start Menu and Desktop shortcuts.

How do I reopen it after closing or killing it?

The toolbar X just hides the window; Ctrl+Shift+A, the tray icon, or Start Menu › Terminal Talk brings it back. If you fully quit or kill it in Task Manager, use the Desktop or Start Menu shortcut.

What's with the coloured dots?

Each tracked assistant session gets a unique solid or split palette marker on the toolbar. Claude Code can show a matching statusline glyph; Codex CLI can show a matching Terminal Talk terminal title; desktop sessions can sync local chat titles where the desktop app exposes enough metadata. You can also give each session its own voice, focus priority, mute state, heartbeat override, and speech rules.

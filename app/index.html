Terminal Talk is for running more than one coding assistant without losing track of who spoke, what is waiting in the queue, and which session needs your attention next.

It turns Claude, Codex, desktop-agent, and highlight-to-speak output into colour-coded audio clips. You keep working in the terminal while the toolbar handles playback, identity, focus, transcripts, and voice routing.

Installed version: …

Intended use

Keep Terminal Talk open while Claude Code, Codex CLI, Codex Desktop, or Claude Desktop Code work in parallel. Let routine progress clips play quietly, focus the session you care about, and use the transcript when you need to inspect the exact spoken text.

  • Use it as a command centre when several assistants are editing, testing, or researching at once.
  • Use it as an accessibility layer when reading long assistant output would slow you down.
  • Use it as a demo layer when you want sessions to narrate what they are doing on screen.

Daily workflow

  • Start your assistant sessions normally or from the Create tab.
  • Give each session a clear label, colour, and voice.
  • Pin or focus the session you want to hear before the others.
  • Let finished response clips auto-prune so the toolbar stays clean.

Playback model

  • Assistant replies become body clips in the queue.
  • Tool narration and heartbeat clips are short ambient status updates.
  • Highlight-to-speak clips are treated as priority user clips.
  • The collapsed strip flashes the colour of the clip that is actually playing.

Session identity

  • Each active assistant gets one slot in the 24-colour palette.
  • Labels are user-owned, so rename sessions around the work they are doing.
  • Focus affects playback priority; mute prevents new audio from that session.
  • Sync pushes identity into supported terminal and desktop surfaces.

Claude and Codex

  • Claude Code uses hooks, transcript files, and footer scraping for turn-end summaries.
  • Codex CLI/Desktop is watched through persisted rollout/session state.
  • Desktop apps can need refresh help because their sidebars cache conversation titles.
  • Nested agents should be treated carefully so one workflow does not impersonate another.

Voice setup

  • Uses Edge voices by default for free local playback.
  • Can use OpenAI TTS as a paid primary voice or fallback when a key is saved.
  • Different voices per session make it easier to recognise speakers by ear.
  • Stores OpenAI credentials outside git and keeps the key hidden after saving.

Toolbar controls

  • Use playback controls for the current clip and transcript controls for inspection.
  • Use Settings > Playback for speed, volume, collapse, prune, and narration behaviour.
  • Use Settings > Sessions for identity, colour, focus, mute, voice, and sync.
  • Use Settings > Shortcuts for global key bindings.

Privacy boundary

  • Wake-word detection runs locally.
  • Terminal Talk reads local assistant logs and local highlighted text.
  • Free TTS uses Edge's voice service; OpenAI TTS only runs when you opt in.
  • Session labels, colours, and playback state live under your user profile.

Good habits

  • Use short labels that describe the work, not the tool.
  • Mute exploratory sessions when they are noisy but not important.
  • Keep focus on the session you want to hear next during busy multi-agent work.
  • Close stale sessions so colour slots stay meaningful.
